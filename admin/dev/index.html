Streamers add themselves in three steps

  1. Send them the sign-up page in a Discord or Twitch message: /start/

  2. They sign in with their own Twitch account. PixFray turns on for that channel only; nobody can turn it on for someone else's.
  3. Watch their row below. After signing in they follow Stream setup on their mod controls page. Setup reaches 3 of 3 when the overlay is open in OBS, the StreamElements Duel module is off and the duel commands answer in chat.

Developer tools: code editor, releases and raw settings

For fixing the site itself. The code editor and releases need GitHub access, and Worker versions need the Cloudflare API; Integrations at the bottom lists what is set up. Running channels don't need any of this.

Code changes and releases run from a local checkout with the gh and cf command-line tools: deploy to staging with npx cf deploy --mode test, check it, then deploy to production. The code editor and release buttons appear here only when GitHub is set up as in docs/LIVE_FIX.md.

Code editor: changes go to a branch, never straight to main

Loads from the branch if it exists, otherwise from main. Secrets, CI files and build output can't be opened here.

Release a fix: test first, then promote or roll back

Each step starts the GitHub Actions deploy workflow. Nothing changes on pixfray.xyz until you promote or use a hotfix.

  1. Save to a branch in the code editor above. Branch names start with live-fix/ or hotfix/.
  2. Deploy to test.
    Uses the branch in the code editor.
  3. Check it in OBS with the test overlay: staging.pixfrayf.xyz overlay.
  4. Promote to production. Squash-merges the pull request, then deploys the base branch.
  5. Roll back if something breaks.

Hotfix: deploys a hotfix/ branch straight to production, skipping the test site (unit tests still run), and opens a pull request so main keeps the change.
