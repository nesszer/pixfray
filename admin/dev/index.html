Release a fix: test first, then promote or roll back

Each step starts the GitHub Actions deploy workflow. Nothing changes on chat.miolaf.xyz until you promote or use a hotfix.

  1. Save to a branch in the code editor above. Branch names start with live-fix/ or hotfix/.
  2. Deploy to test.
    Uses the branch in the code editor.
  3. Check it in OBS with the test overlay: test.chat.miolaf.xyz overlay.
  4. Promote to production. Squash-merges the pull request, then deploys the base branch.
  5. Roll back if something breaks.

Hotfix: deploys a hotfix/ branch straight to production, skipping the test site (unit tests still run), and opens a pull request so main keeps the change.
